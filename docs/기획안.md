# 발주 납기·입고 현황 대시보드 기획안

> 작성: 2026-11 · 기준 자료: 기존에 쓰던 발주 관리 엑셀 (시트: dashboard / po_raw / receipt_raw / po_calc / eta_input)
> 원칙: **지금 쓰는 엑셀 방식을 그대로 웹으로 옮기고, 불편한 부분만 고친다.**

---

## 1. 목적
발주한 패스너가 언제, 얼마나 들어오는지, 처음 납기와 얼마나 달라졌는지, 아직 얼마나 남았는지를 팀이 한 화면에서 같이 본다.

## 2. 사용 환경
- 사내망 전용. 사무실 PC 한 대에서 프로그램을 실행하고, 팀원은 브라우저로 접속한다.
- 권한: **구매팀 = 입력·수정 가능**, **다른 부서 = 조회만 가능**.

## 3. 데이터 넣는 방법 (엑셀과 동일)

| 엑셀 시트 | 웹에서 하는 방법 |
|---|---|
| po_raw | SAP에서 내려받은 발주 파일을 붙여넣기, 또는 **엑셀(.xlsx) 파일 그대로 올리기** |
| receipt_raw | 거래명세서 내용을 지금처럼 덩어리째 붙여넣기. 중간 제목줄·합계줄·빈 줄은 자동으로 무시하고, "10/16 착(용차)"에서 날짜를 읽는다 (연도는 자동으로 붙임). 괄호 안 내용은 메모로 보관. 또는 **공급사 거래명세서 엑셀·PDF(스캔본 포함) 파일 올리기** → 자동으로 읽은 입고일·공급사·품번·수량·PO를 확인·수정 후 저장 (2026-11-13 추가) |
| eta_input | 대시보드에서 해당 줄의 '납기예정일' 칸에 바로 입력 |
| 개발건 | **제외** (Indirect 발주는 표시하지 않음) |

**단가 정보는 다루지 않는다.** 업로드할 때 Price, Price Currency, Document Rate, Row Total, Doc Total Before VAT, VAT, Doc Total, 입고 내역의 Price/Total 열은 저장하지 않고 버린다.

### 새 발주서 반영 방법
- 발주서는 지금처럼 SAP에서 작성·송부한다. 이 프로그램에서 발주서를 만들지는 않는다.
- SAP에서 발주 파일을 내려받아 다시 올리면 된다. 매번 **전체 파일**을 올려도 된다.
- 프로그램은 **같은 발주 줄 기준**(아래 "업로드 가공 규칙" ②)으로 줄을 맞춰 본다.
  - 처음 보는 줄 → 새 발주로 추가 (기존 납기일 = 이때의 Delivery Date)
  - 이미 있는 줄 → 잔량, 상태만 갱신. 기존 납기일과 입력해 둔 납기예정일·이력은 그대로 둔다.
  - Closed가 된 줄 → Closed 날짜 기록 (6개월 뒤 입고 기록 자동 삭제의 기준)
- 올린 뒤 "새 발주 n줄 · 잔량 바뀐 줄 n줄 · Closed n줄"을 요약해서 보여준다.
- 권장: 새 발주서를 작성한 날, 또는 매일 아침 한 번 올리기.

### 업로드 가공 규칙 (발주 파일을 올릴 때마다 프로그램이 자동으로 적용)

**① 삭제할 줄** — 아래 중 하나라도 해당하면 대시보드에 넣지 않는다.

| 열 | 삭제 조건 |
|---|---|
| Purchase Type | Indirect 이거나 비어 있음 |
| Row Status | C 이거나 비어 있음 |
| Price Currency | KRW가 아니거나 비어 있음 |

- Price Currency는 이 판단에만 쓰고 저장하지 않는다. 단가 열은 처음부터 읽지 않는다.
- Row Status가 C로 바뀌어 빠지는 줄은 그날을 Closed 날짜로 기록한다 (6개월 자동 삭제 기준).

**② 중복 제외** — 아래 5가지가 **모두** 같으면 같은 발주 줄로 보고 하나만 남긴다. 하나라도 다르면 별개 줄이다.
> PO number · Posting Date · Delivery Date · Item No. · Vendor Name

- 수량이나 잔량이 서로 다르면 **PO가 수정된 것**이므로 **가장 최근 것**을 남긴다.
  - 가장 최근 = 나중에 올린 파일의 줄. 한 파일 안에서는 더 아래에 있는 줄.
- 기존 엑셀 데이터로 시험했을 때 두 번 붙여넣은 줄과 수정된 PO 줄이 모두 이 규칙으로 정리되는 것을 확인했다.

**③ 납기예정일 유지**
- 새 발주 파일을 올려도 납기예정일은 Delivery Date로 되돌아가지 않는다. **이전에 입력한 납기예정일과 변경 이력이 모두 그대로 적용**된다.
- 연결 기준은 ②의 5가지 항목이다.

## 4. 첫 화면 (대시보드)
엑셀 dashboard 표에서 **Vendor code를 빼고**, **상태** 칸 하나를 추가한다.

| PO number | Vendor name | Item No. | 현재 발주 수량 | 현재 잔량 | 기존 납기일 | 납기예정일 | 상태 |
|---|---|---|---|---|---|---|---|

- 현재 발주 수량 = SAP의 Quantity(처음 발주 수량), 현재 잔량 = SAP의 Remaining Open Quantity
- 마지막 SAP 업로드에서 처음 들어온 발주 줄에는 7일 동안 **신규** 표시를 붙인다.

- 상태: 입고대기 / 부분입고 / 입고완료 / **지연**(빨간색, 납기가 지났는데 잔량이 남은 경우)
- 표 위에 숫자 3개: 지연 건수 · 이번 주 입고예정 · 잔량이 남은 건수
- 검색·필터: 공급사, 품번, PO번호, 상태
- 줄을 클릭하면 상세 정보가 열린다: 납기 변경 이력, 날짜별 입고 수량, 납기 대비 며칠 빨리/늦게 왔는지

## 5. 계산 규칙

### 5-1. 기존 납기일
- SAP Delivery Date를 **처음 받은 값 그대로 항상 표시**한다. 수정 기능은 없다.
- 나중에 SAP 파일의 값이 달라져도 덮어쓰지 않고 "SAP 값 변경됨" 표시만 한다.

### 5-2. 납기예정일
- 입력은 한 칸이다. 바꿀 때마다 이전 값을 자동으로 보관한다 (이력으로 조회 가능).
- 줄은 **PO number · Posting Date · Delivery Date · Item No. · Vendor Name** 5가지로 구분한다 (업로드 가공 규칙 ②와 같음). 엑셀에서는 PO+업체+품번+수량이 같은 줄에 같은 날짜가 함께 들어가는 문제가 있었는데, Delivery Date가 기준에 들어가므로 납기가 다른 분할 줄은 따로 관리된다.

### 5-3. 현재 잔량
> **현재 잔량 = SAP 잔량 − 아직 SAP에서 확인 안 된 등록 입고** (2026-11-13 변경)

- 거래명세서를 올리는 즉시 입고일과 상관없이 대시보드 잔량에 반영한다 (PO 작성일 순 FIFO).
- 새 SAP 발주 목록(B)을 올릴 때마다 지금 현황판(A)과 대조한다. PO number + PO Line으로 새 발주를 빼고, 공급사+품번별로 잔량을 비교한다.
  - 일치 → SAP 반영 완료
  - 차이가 최근 2일(입고일 또는 등록일) 입고와 일치 → 아직 SAP 반영 대기
  - 그 밖 → "확인 필요" 표시 (이중 입고·미등록 입고 확인)
- 입고 기록은 **참고용**이다: 날짜별 입고 수량, 납기 대비 며칠 빨리/늦게 왔는지 보는 데 쓴다.

### 5-4. FIFO (입고 기록을 어느 PO 줄에 붙일지)
- 등록한 입고를 어느 PO 줄 잔량에서 뺄지 정하고, "이 줄은 언제 얼마씩 들어왔나"를 보여주는 데 쓴다. 거래명세서의 PO 번호와 상관없이 앞 발주의 잔량부터 채운다.
- 같은 **공급사 + 품번**의 입고량을 **PO 작성일(Posting Date)이 빠른 순서**로 채워 나간다.
- 작성일이 같으면 PO번호, 그다음 PO Line 순서로 채운다.

### 5-5. 자동 삭제
- PO가 **Closed로 바뀐 날부터 6개월**이 지나면 해당 입고 기록을 자동으로 삭제한다.
- SAP 파일을 올릴 때마다 상태를 비교해서 Closed가 된 날짜를 프로그램이 기록한다. 발주서 날짜는 기준으로 쓰지 않는다.
- 필요하면 지금처럼 직접 지울 수도 있다.
